# 本地以文搜图

beta4 的本地搜索为可选功能，默认关闭。基础选片、质量分析、场景分组不依赖搜索模型。索引与查询均在本机运行，不调用云端接口。

在选片页展开「本地搜索」，点击「检查本地检索模型」。模型检查通过后，点击「建立 / 补全检索索引」，完成后刷新状态，再输入描述搜索。未建立索引的照片不会出现在结果中；结果同时显示索引覆盖量。索引任务沿用任务面板的暂停、继续和取消，浏览照片不会自动启动索引。匹配度衡量查询与图片的向量关系，不是画质分数或正确率。

## 准备模型

本版本提供兼容的本地双编码器运行入口，**没有附带或自动下载检索权重**。使用者需选择有权使用的模型，并自行确认权重、分词器、转换产物和用途符合其许可。软件不会替使用者接受许可。

在应用使用的模型目录中，准备 `optional/retrieval/`，其中包含：

- `image.onnx`：图像编码器。
- `text.onnx`：与图像编码器来自同一模型、同一训练空间的文本编码器。
- `tokenizer.json`：该模型对应的 Hugging Face Tokenizers 完整分词配置。
- `config.json`：下面列出的兼容信息和实际文件哈希。

模型目录通常与其他本地权重共用；开发环境为仓库忽略目录 `models/`。这些文件不应提交进源码。仅放入两个名称相似的 ONNX 文件不足以证明它们兼容。

`config.json` 的字段如下；具体数值必须来自所选模型和实际导出文件，不要猜测：

| 字段                                              | 要求                                        |
| ------------------------------------------------- | ------------------------------------------- |
| `provider`                                        | 固定为 `clip_dual_encoder_v1`               |
| `label`                                           | 可辨认的模型名称                            |
| `license_reviewed`                                | 由使用者确认后设置为 `true`；软件不自动写入 |
| `image_sha256`、`text_sha256`、`tokenizer_sha256` | 各文件的完整 SHA-256，64 位十六进制         |
| `dimensions`                                      | 图文共同向量维数，2–2048                    |
| `context_length`                                  | 固定文本长度，4–256                         |
| `bos_token_id`、`eos_token_id`、`pad_token_id`    | 与对应分词器、文本编码器一致的 token ID     |

兼容约束：

- 图像输入 `pixel_values` 为 float32 `[1,3,224,224]`；输出 `image_embeds` 为 float32 `[1,dimensions]`。
- 图像处理固定为 RGB、短边 224、中心裁切、Catmull-Rom 缩放、CLIP mean/std；不支持其他分辨率或归一化方案冒充兼容。
- 文本输入 `input_ids` 为 int64 `[1,context_length]`；可带同形状 int64 `attention_mask`；输出 `text_embeds` 为 float32 `[1,dimensions]`。
- 分词器完成自身正规化和后处理，程序检查 BOS/EOS、固定截断和补齐，再对图文输出作 L2 归一化。
- 当前限制为每个 ONNX 文件不超过 512 MiB、分词器不超过 32 MiB。不兼容的张量名称、类型、形状或特殊 token 会明确失败，不生成假结果。

检查状态 `ready` 只代表配置、文件和哈希检查通过；首次推理还会验证运行契约。模型对中文、长句、摄影术语的理解能力取决于训练数据，不能由接口兼容性推断。

## 索引与性能边界

图片向量保存在本地数据库，按模型空间、预处理、照片修改时间和大小检查兼容性。只修改质量评分权重不会重建检索向量。替换模型、分词器或输入照片后，旧向量不会参与新空间的搜索。

索引使用一个可取消的隔离工作进程，并依据当前浏览位置调整待处理顺序。文本查询单独限流，使用隔离工作进程和超时保护；当前每次文本查询会冷启动模型。搜索为精确余弦扫描并保留前若干项，尚未引入近似索引。没有对十万张照片或具体真实检索权重承诺响应时间。

自动化测试使用生成的 ONNX 图、合成颜色图片和临时数据库，验证真实本地推理、分词、向量归一化、索引失效与排名流程；这不等于公开人像上的语义检索准确率验收。
