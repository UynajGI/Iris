# 架构

| 层         | 实现                     | 职责                                                         |
| :--------- | :----------------------- | :----------------------------------------------------------- |
| 数据与计算 | `iris-core`              | SQLite、扫描、解码、ONNX、评分、分组、编辑历史与文件操作     |
| 浮点渲染   | `iris-render`            | 线性 Rec.2020 D65 FP32、传统编辑图、颜色管理与成片编码       |
| 本地服务   | `iris-daemon`            | HTTP/OpenAPI/WS、后台任务、独立分析 worker、模型安装         |
| 无界面入口 | `iris-cli` / `iris-mcp`  | 命令行与 SDK stdio MCP，复用业务服务                         |
| 应用与界面 | `apps/shell`             | TypeScript 状态/生成 API、React、Tauri 托管                  |
| RAW 后备   | `components/raw-decoder` | MIT 包装器调用 LGPL rawler，JSON/PPM8 与版本化 FP32 文件协议 |

MCP 属于服务层另一种入口，在进程内调用现有路由，不启动 HTTP 监听。GUI、CLI、MCP 使用相同数据库时，由进程所有权锁排除并发写入。

扫描使用独立数据库连接，并行读取元数据，先提交首项再分批写入，让界面在扫描完成前读取已提交照片。普通名称排序画册在 SQL 中分页，避免为一页读取全库分析。分析另行启动，基础分数先发布，语义候选随后分组；CPU worker 有界并行并保留交互资源。任务支持暂停、恢复、取消和失败隔离。DINO 只计算候选向量并缓存，兼容的语义阈值变更复用向量。缺少可选能力时显式报告回退；哈希错误的工件不能靠缓存绕过检查。

beta4 的 schema v7 通过触发器维护 `analysis_catalog` 查询投影；当前性、决定/星级/颜色与排序分页先在 SQLite 执行，完整分析 JSON 在页内读取。场景归属表仅保存人工修正，自动场景根据时间与锚点外观重新形成候选；它与连拍、重复组独立。细节测量以照片指纹、区域和方法为键写入独立缓存，不依赖质量权重。

当前数据库为 schema v9：在既有选片数据上加入版本化编辑文档、虚拟副本、撤销重做、预设、内容寻址资源及固定快照成片导出日志。迁移前备份；人工选片决定与编辑历史分别保存。`iris-core` 负责来源、修订、资源与事务校验，`iris-render` 执行传统浮点计算，HTTP、CLI、MCP 只编排各自公开的共享入口。

编辑预览与选片 JPEG 缓存分开。服务锁内准备不可变任务，锁外哈希、解码、渲染与编码；草稿预览不写历史，客户端确认后再保存。预览按会话递增序列取消过时结果，固定版本导出持久排队并以禁止覆盖方式发布。配置、原尺寸区域的完整帧计算限制、RAW/ICC/GPU 边界及当前 CI 状态见[传统调色后端实现](color-engine-implementation.md)。这些后端入口不表示调色前端或整阶段验收已完成。

浏览上下文带客户端身份和递增修订号，30 秒过期，迟到修订不会覆盖当前状态。质量、DINO 与可选检索索引共享有界领取策略，焦点、比较、邻近成员依次优先，每四次优先领取保留一次 FIFO；已领取工作不重复执行。

可选图文搜索使用兼容的本地 ONNX 双编码器和固定分词器，图像向量持久化到 `retrieval_embeddings`，依据输入指纹与模型空间失效。检索进程与质量进程隔离；图像索引全局限一个任务，文本查询另行限流。查询为精确余弦扫描，默认不启用、不下载模型。细节证据、几何人脸对应和相似度均不能替代人工取舍。完整约束见[本地搜索](local-search.md)。

JPEG 使用 reduced-IDCT；其他格式实行输入/像素/解码缓冲限制，HEIC 优先选择适用的内嵌缩略图。选片 RAW 先提取 JPEG，再调用独立开发器；高精度编辑直接使用单独的 FP32 显影协议，不复用此 RGB8 路径。这不是整个进程恒定内存的保证。

预览只在短服务锁内准备路径与指纹，解码和缓存发布移出锁。daemon 限制同时解码与后台预取，优先处理前台照片；前端共享请求租约，取消过时工作并延迟屏外缩略图。RAW 子进程可取消，已进入原生栅格解码的调用完成后丢弃过时结果。

Windows DirectML 可选，设备与回退可观察。worker 启动握手报告具体运行库选择；完整运行库不可用时扩展 CPU 池，保留原始设置与缓存身份。前端 Auto 策略和后端执行提供器是不同概念；跨平台设计不表示所有 GPU/媒体后端已经适配。

原照片、人工决定与算法建议分开管理。隔离、恢复、复制、导出和缓存治理走领域校验与日志，不自动永久删除原照片。MCP 另有允许目录、只读模式、写入请求 ID 和审计。

事务见 [core-services.md](core-services.md)，协议见 [api-contract.md](api-contract.md)，证据见 [validation.md](validation.md)。

源码按职责分模块：前端入口负责应用装配，工作区组件与状态 hooks 独立；core `services/` 按业务领域组织，daemon `operations/` 按路由职责组织；CLI 分离参数与命令执行，MCP 分离调用调度与授权。入口继续共享核心服务，不复制业务逻辑。拆分范围、复杂度命令与剩余风险见[复杂度检查](complexity.md)。

发行层复用已验证的便携载荷，不复制业务逻辑。Windows NSIS 保持相邻 daemon/模型布局；
macOS PKG 将自包含 App 安装到 Applications，Linux DEB 将载荷放在 `/opt/iris` 并提供 PATH/菜单入口。
版本化安装界面、对应源码和完整发行附件门禁由[发布流程](releasing.md)管理，解包验证不等于真实安装或签名验收。
