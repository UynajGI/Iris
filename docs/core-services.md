# 数据与领域服务实现

`iris-core::Store` 使用 SQLite WAL、外键、FULL 同步和 schema 版本管理。旧库迁移前通过 SQLite 在线备份 API 创建独立备份；新版本库拒绝由旧程序打开。`recovery_notice` 提供备份位置。决策、撤销、分析、档案、设置及隔离清单均持久保存，重启后可恢复。

`iris-core::Services` 是 daemon 与 CLI 共享的领域入口。类型位于 `domain.rs`，序列化字段使用 snake_case；照片和项目 id 为整数。扫描识别 JPEG、PNG、WebP、HEIC/HEIF 及列举的 RAW 扩展名，不跟随符号链接，跳过 `.iris`、`.iris-cache`、`.iris-quarantine`。RAW 使用 ExifTool 嵌入JPEG及 rawler 后备解码。格式、运行库及资源限制见[媒体支持](media-support.md)。

daemon每个项目分析池默认上限12，可用`--worker-limit 1..16`在启动时调整；实际
数量取配置、可用逻辑CPU和待处理照片数的最小值，全缓存仍不启动模型进程。
例如`iris-daemon.exe --worker-limit 8 --data-dir .iris --model-dir models`限制该daemon
每个项目的分析池至多8个worker。该参数不属于评分设置，不改变分析版本或缓存
指纹，也不是所有项目共享的全局进程/内存上限；并行项目有各自的分析池。

扫描通过相对路径、纳秒 mtime 和文件大小判断增量；尺寸与 EXIF 拍摄时间读取无需全图解码。变更会使分析失效，损坏的替换文件也不能继续沿用旧建议。取消保留已完成部分；只有无错误的完整扫描才标记丢失照片，避免取消或目录错误误伤图库。

HTTP扫描结束时以最终ScanReport同步进度，不依赖最后一次成功照片回调。存在错误
时终态为`failed`，主动取消优先为`cancelled`；错误与成功导入的部分图库均保留。
`completed`计成功新增/变更/未变和跳过项，错误单列（包含目录错误，不能作为照片
数量相加），终态`total`与该已处理计数一致。只有损坏文件的项目会返回失败、0/0
及非空错误；只有跳过文件的项目计数仍完整。

人工、批量采纳及 CSV 导入各形成可撤销事务。一键采纳仅处理 pending，保留人工结果，review 不采纳；即使数据库中 verdict 与闭眼标记矛盾，也不会自动采纳该照片。RAW+JPEG拍摄变体可联动，已有相反决策会报告冲突并保留。同拍摄且决定相同的RAW+JPEG导出共享一份XMP；其他路径碰撞仍拒绝。

批量采纳可用 `AcceptRequest {photo_ids?, category?}` 限定成员和
`all/recommend/reject_suggest` 类别。省略 ID 表示全项目，显式空数组不做操作；
非空 HTTP 请求体始终解析，错误格式不会降级为全项目采纳。显式 ID 先验证归属
和可用状态，重复 ID 去重。待采纳候选须符合当前分析版本、规范化设置和源指纹，
任一过期候选使整批拒绝；成功形成一个撤销事务。

设置和档案按视觉引擎的参数结构严格校验。评分权重或阈值变化时，仅对版本和原设置匹配的当前特征在同一事务内重算；旧版本不能通过调权伪装成当前分析。检测参数、NIQE开关、可选遮挡参数或执行提供器/设备变化时使特征失效。仅DINO提供器、哈希、语义阈值变化则保留基础特征，按候选与向量身份复用或补算嵌入；单独缺向量不意味着基础分析过期。档案预估比较规范化设置键的并集，包含从当前设置中删除的可选字段，排除旧/缺/设置不匹配记录；即使档案设置未变，也报告这些不可估计样本需要刷新。人工决定独立保留。

schema v2 持久保存 `Project.groups_dirty`：照片成员/特征或设置变化时，数据库触发器在同一事务清除旧分组并标记待重建；成功保存分组后清除标记。合法的零分组结果不等于未完成。`Project.pending_analysis` 统计全项目有效照片中缺少当前引擎版本分析的数量，不受图库分页影响；取消或部分失败后仍可识别待处理照片。新建空项目不要求分析，旧库升级时保守标记待重建。

当前 schema v3 新增 `last_opened_at`、`hidden` 和缓存迁移清单表。创建/显式打开
更新最近顺序并取消隐藏；项目列表省略隐藏项，GET详情、进度轮询和桌面重连不改变
打开时间。隐藏不删除项目或照片。v1/v2升级仍先备份；v5版本的真实100张v2快照
验证确认schema升级成功、旧v4特征必须重新分析、人工决定保留。刷新后100张当前
结果可无模型零worker复用，原始快照内容不变。每张 `analysis_status` 依据已扫描
记录的分析版本和规范化设置区分缺失/当前/过期，不是对外部文件的实时监视。
历史分析仍可读取，但只有`current`分析参与verdict筛选、评分排序和新分组。
部分重分析失败时，只对当前有效子集建组；成功保存该分组可清除`groups_dirty`，
而失败或过期照片仍由`pending_analysis`报告，不把历史分数当作当前建议。

进度轮询只做项目主键存在性检查，然后读取作业状态；不会为每次轮询计算整库
待分析数量。项目详情仍提供完整就绪统计。事件构造移动已有分析JSON，保持对外
嵌套数据和WebSocket契约；这些优化不改变单图事务耐久性、源指纹或设置并发检查。

导出与文件安全：

- XMP 仅创建 sidecar。写入前检查整个选中集合的目标路径；`a.jpg` 与 `a.jpeg` 等共用sidecar的记录会使整批提前报错，Windows下也检查大小写碰撞，两种覆盖模式均不写任何选中项。无集合内冲突时，默认跳过已有文件；显式覆盖先保留旧 sidecar 的唯一备份，照片内容不变。
- 精选复制保留项目相对目录，创建新文件并比较 SHA-256。已有目标跳过，目标不能位于原项目目录内。
- CSV 使用 `path,action` 两列，导入先验证全部行再提交一个事务；未知路径、重复路径、非法决策和路径穿越会拒绝整次导入。
- 隔离预览不移动文件，保存选中照片、目标、大小和 SHA-256。commit 重新检查决定和源内容后才执行复制、校验、删除源文件，每一步先写日志。
- 隔离恢复验证日志路径和文件哈希，绝不覆盖不同内容。若进程在复制后、删除源前退出，恢复会识别两个相同副本并保留源。`quarantine_history` 和 `quarantine_plan` 可用于恢复提示。
- 恢复先预检整个清单；执行前持久记录每项文件存在状态、数据库标记和原清单状态。中途失败反向补偿已执行项；补偿失败保留 `restore_rollback_failed` 与剩余日志，下一次恢复先续补偿再重新恢复。复制后删除前的双副本也按原状态恢复。SQLite 故障注入覆盖恢复/补偿失败与重启续做。
- 缩略图和预览按照片指纹及尺寸缓存。不裁切，320px 缩略图由有界预览再缩放，2560px 预览按需生成。缓存先写完并关闭同目录临时文件，再不覆盖地发布；Windows使用同卷重命名，不要求缓存卷支持硬链接，其他平台保留硬链接路径。已有并发目标不被截断或替换。
- 缓存迁移先复制校验全部文件再切换数据库位置，原缓存保留；失败不会改变有效缓存位置。
- 迁移历史持久保存原/新根目录及逐文件路径、大小、SHA-256和清理状态。按项目与迁移ID显式确认后才清理旧文件，先全清单预检，再逐项重验原件和迁移副本；每项进度持久保存，删除后未记账也可重试。未列文件与目录保留。所有项目（含隐藏）的照片和其他当前缓存均受保护；程序在自身照片根下的`.iris/cache/...`或`.iris-cache/...`允许管理，但其中存在已登记照片时拒绝清理。

`crates/iris-core/tests/services.rs` 覆盖增量扫描、重启撤销、人工决定保留、变体冲突、设置预估与失效、XMP/复制/CSV、隔离陈旧预览和崩溃恢复、缓存迁移、备份迁移及损坏数据拒绝。真实照片端到端、模型质量和性能验收需分别以集成测试和实测报告证明；这些领域测试不替代视觉质量评测。
