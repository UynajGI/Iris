# 调色草稿恢复

2026-10-16：第一阶段前端加入同一窗口内的草稿暂存和恢复，不改变后端编辑历史合同。

## 行为

- 未保存的文档、基础版本和未确认的保存请求暂存在当前窗口的 `sessionStorage`。不暂存照片像素、服务令牌或预览 Blob。
- 连续输入只更新内存引用，最多每 250ms 合并持久化一次；页面隐藏、刷新离开和编辑器卸载时补写。单条暂存内容限制为 2MiB 字符，配额或权限失败时保留内存和上一次成功写入的副本，并提示及时保存。
- 打开照片或切换调色版本时，以编辑 ID、照片 ID、源文件指纹和基础版本核对暂存内容。版本未变时恢复未保存调整，恢复前先由后端验证整个图文档，不直接将损坏的本地 JSON 交给控件。
- 如果保存请求实际已提交但响应丢失，重连时保留其请求 ID；可以识别已提交的文档，并保留等待期间产生的更新输入。服务回复不会覆盖较新的未保存输入。
- 如果服务端版本已更新，不自动覆盖或合并。界面锁定修改并提供“恢复为副本”和“放弃草稿”；恢复前重新读取最新版本，验证草稿后创建独立副本。恢复副本仍需用户保存。
- 保存成功或明确放弃后清除对应暂存内容。窗口之间不共用这份暂存区，避免互相覆盖。

## 验证

本地前端 234 项通过、0 失败、1 项原有跳过；类型检查与构建通过。新增 13 项测试覆盖暂存合并、读取损坏、配额失败、版本/源冲突、丢失保存回执、新输入保留、恢复前校验、取消和独立副本。

浏览器使用 PPR10K 临时项目中 `1025_1025_10.jpg` 的独立副本：未保存曝光 `1.25` 后刷新，数值与未保存状态恢复；该副本在服务器上仍是版本 0，恢复没有暗中保存。随后模拟另一个客户端以版本检查将曝光保存为 `-0.5`，再次刷新触发冲突提示；“恢复为副本”创建新版本，保存后后端读回曝光 `1.25`，并发版本仍为 `-0.5`，原始调整仍为版本 0、曝光 0。保存后再次刷新不再出现恢复提示。测试结束已切回原始调整。

## 边界

这是同一窗口的断线/页面刷新恢复，不是跨设备或退出应用后的云端恢复。浏览器或 WebView 终止且未触发生命周期事件时，最近一个暂存周期内的输入可能未落盘；关闭窗口后的保留取决于宿主会话存储，不保证恢复。原生退出保护仍独立生效，其完整平台验证没有由本次浏览器测试替代。原片指纹或图资源不再匹配时由后端拒绝恢复，不自行迁移相机配置或蒙版坐标。
